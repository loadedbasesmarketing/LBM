# design-taste

Run this process in order on every UI build. Do not skip steps. Do not show the user anything until step 9 passes.

## 1. Read taste.md first
`taste.md` outranks every other file in this skill. If a rule there conflicts with principles, directions or tells, taste.md wins.

## 2. Read references/principles.md
These are the measured patterns from the studied sites. If the file still says PENDING, tell the user the study has not been done, and work only from taste.md and the tells.

## 3. Read references/ai-slop-tells.md
Know every named tell before writing a line of CSS.

## 4. Pick ONE direction
Open `references/directions.md`. Pick exactly one direction. State in one sentence why it fits this audience and this page's single job. Never blend two.

## 5. Pull two or three real references
Use `references/sources.md` to choose the galleries for that direction. Pick two or three live sites. Fill `prompts/reference-brief.md` once per reference.

## 6. Write the take/leave brief
For each reference: what to take (patterns only: scale ratio, grid, spacing rhythm, motion timing) and what to leave. Never copy assets, logos, photos or copy.

## 7. Build in this order
1. Type: pick the families, set the scale (largest heading to body ratio), line heights, weights.
2. Spacing: one spacing scale, applied everywhere.
3. Colour: palette count and roles, taken from the direction.
4. Layout last: grid, section order, hero composition.

## 8. Screenshot
Render with Playwright at 1440 wide and 390 wide, full page. Look at both screenshots yourself.

## 9. Run the checklist
Run the 8-point checklist at the end of `references/ai-slop-tells.md` against both screenshots. Every "yes" is a hit. Fix every hit, re-screenshot, re-run. Only show the user the result once every answer passes.

## 10. Record the verdict
When the user approves or rejects anything, add one line to `taste.md` under Approved or Rejected:
`YYYY-MM-DD | what they said | the rule it implies`
